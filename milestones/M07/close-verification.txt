AND ONE OF THEM WAS STALE. FOUND BY RE-RUNNING IT AT CLOSE.
--------------------------------------------------------------------------

`ci_eval_role_mutations.py` did NOT report 0/5 on the first run at close. It
reported:

  1 survivor(s) out of 5: sub widened to repo:andaro74/regdelta:*
                          — any ref in this repo (anchor matched 0x)

The mutation could not find the text it mutates. `ci-eval-role-mutations.txt`
had been recorded when the OIDC trust policy pinned

  "token.actions.githubusercontent.com:sub": "repo:andaro74/regdelta:pull_request"

and that string stopped existing hours later, when PR #17 measured the claim
GitHub actually issues and the subject was re-pinned to the IMMUTABLE form:

  "repo:andaro74@3157440/regdelta@1322516232" ":pull_request"

The artifact was never re-run afterwards. So the evidence pack was carrying
"0 survivors out of 5" about a file that no longer contained what the probe
mutates — a verified-looking claim about code that had changed underneath it.

  THE PROPERTY WAS NEVER UNDEFENDED. `test_the_subject_claim_is_scoped_to_
  the_event_not_just_the_repo` asserts the exact expected subject, that it
  still ends `:pull_request`, that no `*` appears in it, and that no
  StringLike sneaks a wildcard in the back door. All of that held throughout.
  What was missing was the PROOF that the test would notice if it stopped
  holding. That is the entire purpose of a mutation suite, and for those
  hours the suite was asserting it about text that was not there.

Fixed by re-anchoring the mutation on the current two-line form and re-running:
5/5 applied, 0 survivors, core_stack.py restored byte-for-byte.
`ci-eval-role-mutations.txt` re-recorded.

  IT WAS CATCHABLE ONLY BECAUSE THE RUNNER DISTINGUISHES "NOT APPLIED" FROM
  "KILLED". A suite that counted an un-applied mutation as a pass would have
  reported 0/5 and been wrong, silently, for as long as anyone cared to look.
  That distinction was built into this runner in response to the CRLF defect
  documented at the top of the same file — where five multi-line anchors
  matched 0x after an in-place rewrite. It has now paid for itself twice, for
  two unrelated causes.

  The general shape is M07's own: a measurement that was true when taken, and
  an artifact that goes on asserting it after the thing measured has moved.
  Same family as `unit` being "green" on this laptop only, and as the eval
  gate's three wrong diagnoses. The countermeasure is the same one every time
  — re-run it where it matters, and build instruments that can say "I did not
  actually check" instead of returning a pass.
