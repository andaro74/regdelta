# Dev + CI tooling. `pip install -r requirements-dev.txt` gives you exactly what
# the eval gate runs, which is the point: a lint or test that passes here and
# fails in CI is a version drift, not a finding.
#
# Found at M03: CI pinned ruff==0.16.2 while this laptop had 0.16.1. The pin's
# stated purpose is that "identical code passes or fails identically regardless
# of the day of the pip resolve" — which it cannot do if local and CI pin
# different versions. One file now, so they cannot diverge again.
-r requirements.txt

# Rule SELECTION lives in ruff.toml, also explicit. Both halves matter: the
# version fixes what the rules mean, ruff.toml fixes which rules apply.
ruff==0.16.2
pytest==9.1.1

# is an httpx transport over the ASGI app, with no server and no socket.

# mangum, langgraph or boto3 requires httpx, so it was present on the laptop by

# Parses .github/workflows/evals.yml for tests/test_eval_gate_workflow.py, which
# asserts each job holds exactly the permissions its steps need. TEST-ONLY:
# nothing in src/ or infra/ reads YAML.
#
# ALREADY PRESENT, AND THAT IS THE REASON TO PIN IT RATHER THAN NOT TO.
# `langgraph -> langchain-core -> pyyaml<7.0.0,>=5.3.0` resolves it to 6.0.3 in
# CI today, so the guard would import and pass with nothing declared — which is
# exactly how httpx and aws-cdk-lib got here. Both were ambient until CI and the
# laptop diverged, and this file's whole premise is that a test passing in one
# place and failing in the other is a version drift rather than a finding.
#
# A langchain-core release dropping pyyaml would otherwise take the eval gate's
# own permissions guard down for a reason nothing in this repo names.
#
# Worth stating plainly: evals.yml declined this guard in 2026-08 partly because
# "PyYAML is not transitive from boto3, langgraph, fastapi, starlette, mangum or
# ruff, so it would have had to become a dependency." That was wrong — it is
# transitive from langgraph — and the pin is here anyway, because being
# transitive is a property of this week's resolve and not a declaration.
pyyaml==6.0.3

# The infra tests. `tests/test_search_stack_access.py` opens with
# `pytest.importorskip("aws_cdk")`, and aws-cdk-lib lived only in
# infra/requirements.txt — which the eval gate's unit job does not install. So
# the whole module reported as `1 skipped` in CI while passing locally: 713
# tests there against 733 here.
#
# That is this file's stated purpose failing in the direction it was written to
# prevent, and the skip is the dangerous shape of it — a red test says
# something, a silent skip says nothing. What was not running: the AOSS
# data-access policy tests, which are the whole of AOSS authorization, and the
# two written at M04 after the reindex Lambda shipped an asset containing no
# source and leaking a root-level .env. Neither would have caught a
# re-introduction of that defect on the machine that gates merges.
#
# Pinned to what the laptop resolves, like everything else here. It satisfies
# the >=2.230.0 floor infra/requirements.txt carries.
#
# WHAT THIS PIN DOES NOT COVER, said plainly because the header above claims
# this file gives you "exactly what the eval gate runs". aws-cdk-lib pulls eight
# packages named nowhere here, and three of them FLOAT:
# aws-cdk.asset-node-proxy-agent-v6, aws-cdk.cloud-assembly-schema (>=54.11.0)
# and — the one that matters — jsii (>=1.138.0,<2.0.0). jsii is the Python-to-
# Node bridge that runs the bundled JavaScript doing asset staging, which is
# precisely what tests/test_search_stack_access.py's allowlist tests exercise.
# A jsii release can therefore move staging behaviour under a frozen
# aws-cdk-lib pin, and CI would be testing something the laptop is not. Today
# only two jsii versions satisfy the range, so the exposure is narrow — but
# that is a property of this week, not of the constraint. security-reviewer M1;
# whether to pin the transitives too is a dependency decision, so it is on file
# in milestones/M04/README.md rather than taken here.
aws-cdk-lib==2.263.0
constructs==10.8.1
